# 微信头像昵称与阿里云 OSS 设计

## 目标

用户在微信小游戏主菜单首次进入时，可主动授权昵称与头像。昵称和头像最终保存到业务用户资料中；头像由后端转存到阿里云 OSS，客户端不接触 OSS 凭据。

## 范围

- 客户端：首次资料授权弹层、微信用户信息授权、资料展示与重试。
- 后端：当前登录用户资料更新接口、微信头像下载与校验、OSS 转存。
- 复用：将 OSS 上传能力封装为独立公共工具，业务模块不能直接依赖阿里云 SDK。

不包含好友关系、游戏社交数据、客户端直传 OSS 和用户相册头像选择。

## 用户流程

1. 用户首次进入主菜单时显示“完善游戏资料”弹层，并可跳过。
2. 用户点击微信原生用户信息授权按钮，客户端取得昵称和微信头像 URL。
3. 客户端携带现有 JWT 调用后端资料更新接口。
4. 后端校验当前用户身份与输入；下载头像 URL，校验文件大小与图片类型。
5. 后端通过公共 OSS 工具上传头像，取得永久访问 URL。
6. 后端在同次资料更新中保存昵称和 OSS URL，并返回最新用户资料。
7. OSS 未配置、下载失败或上传失败时，接口返回明确错误；用户仍可进入游戏并稍后重试。

## 客户端设计

- 使用 `wx.createUserInfoButton` 发起用户主动授权；不申请朋友关系和游戏社交数据。
- 默认资料入口为首次进入主菜单弹层。用户跳过后，不影响登录、签到或对局。
- 已授权或更新成功后，使用服务端返回的昵称和 OSS 头像 URL 更新本地登录资料缓存。
- 非微信环境保留当前本地预览流程，不尝试调用微信 API。

## 后端设计

### 资料接口

- 新增需 JWT 鉴权的“更新当前用户资料”接口。
- 用户 ID 只能从 JWT claims 读取，不接受客户端指定用户 ID。
- 请求只接受 `nickname` 和 `avatarUrl`；昵称清理首尾空格并限制长度。
- 更新成功响应返回用户 ID、昵称和 OSS 头像 URL。

### OSS 公共工具

- 独立提供初始化、上传图片和返回公开 URL 的能力。
- 从部署环境读取 `ALIYUN_OSS_ENDPOINT`、`ALIYUN_OSS_BUCKET`、`ALIYUN_OSS_ACCESS_KEY_ID`、`ALIYUN_OSS_ACCESS_KEY_SECRET`；缺失时返回配置错误。
- 工具不记录 Access Key、Secret 或完整带签名请求。
- 对象键按用户 ID 和随机文件名生成，避免客户端传入对象键或覆盖其他用户文件。

### 头像转存

- 只允许 HTTPS 头像 URL，并限制为微信头像域名。
- 限制响应体大小，校验 MIME 类型为 JPEG、PNG 或 WebP。
- 下载与上传均设置超时；失败不写入半成品资料。

## 测试与验证

- 后端覆盖未鉴权、越权用户 ID、昵称校验、OSS 配置缺失、头像下载或上传失败、成功更新。
- OSS 工具通过接口注入客户端，测试使用假实现，不访问真实 OSS。
- 客户端验证授权成功、用户拒绝、资料接口失败和跳过资料弹层四种状态。
- 发布前以微信开发者工具和真机验证原生授权按钮与隐私协议。

## 配置与安全

- 凭据仅在部署环境配置；不写入仓库、客户端、日志或设计文档。
- OSS Bucket 仅授予所需写入权限；公开读取策略只覆盖头像前缀。
