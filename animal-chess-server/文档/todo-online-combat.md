## 📅 阶段一：Go 后端基础搭建与连接管理

- [ ] **1.1 初始化 Go 项目与依赖**
  - [ ] 创建后端目录并初始化 Go 模块：`go mod init animal-chess-server`
  - [ ] 下载 gorilla/websocket 依赖：`go get github.com/gorilla/websocket`
  - [ ] 配置基本的目录结构（如 `main.go`, `hub/`, `room/`, `client/`）

- [ ] **1.2 编写 WebSocket 升级器与最简服务器**
  - [ ] 编写标准 HTTP 握手升级为 WebSocket 的 Handler 路由（如 `/ws`）
  - [ ] 实现跨域配置（AllowAllOrigins），方便 Cocos 本地预览调试
  - [ ] 实现 Client 结构体，封装连接对象，并启动 `ReadPump` 和 `WritePump` 协程

- [ ] **1.3 实现心跳检测与保活**
  - [ ] 在 `WritePump` 中定时（如 5s）发送 WebSocket Ping 包
  - [ ] 在 `ReadPump` 中接收 Pong 包并更新 Client 的最后活跃时间
  - [ ] 设置连接超时自动清理机制，防止死连接占用服务器内存

## 📅 阶段二：Go 后端大厅匹配与房间机制

- [ ] **2.1 设计全局 Hub 与匹配队列**
  - [ ] 实现全局管理器 `Hub` 结构体，管理当前在线玩家 Map
  - [ ] 实现一个并发安全的匹配队列 `MatchQueue`（使用带缓冲的通道或双向链表加锁）
  - [ ] 实现匹配服务协程 `StartMatchmaker()`，循环检测队列，每当凑足 2 人则创建房间

- [ ] **2.2 设计房间 Room 结构体**
  - [ ] 定义 `Room` 结构，包含 `RoomID`、`PlayerRed` (红方客户端)、`PlayerBlue` (蓝方客户端)
  - [ ] 在 `Room` 中维护简易的棋局状态 `BoardState` (`map[string]Position`)，记录棋子 ID 与其当前坐标的映射
  - [ ] 实现匹配成功通知：向配对的两个 Client 发送 `match_success` 消息，分发各自的阵营（红/蓝）和初始棋子布局

- [ ] **2.3 实现房间内的消息路由**
  - [ ] 在 `Room` 中处理玩家的 `move` 请求：不进行合法性校验，直接修改内存中 `BoardState` 的棋子坐标
  - [ ] 实现消息广播：将玩家 A 发送的 `move` 动作广播给玩家 B
  - [ ] 处理客户端上报的 `game_over` 消息，广播对局结果并解散/销毁当前房间

## 📅 阶段四：高级联机体验优化（掉线重连与游戏性）

- [ ] **4.1 掉线重连机制（后端支持）**
  - [ ] 当 WebSocket 连接断开时，不要立刻销毁房间，将房间的玩家状态标记为 `Disconnected` 并开启 60s 倒计时
  - [ ] 客户端网络中断时，尝试进行自动重连，携带玩家 `UserID` 和先前的 `RoomID` 发起握手
  - [ ] 服务端识别重连请求，绑定新的连接对象，并将保存在 Room 内存中的 `BoardState` 完整快照下发给重连玩家，客户端重新定位棋子

- [ ] **4.2 回合倒计时与强退判定**
  - [ ] 服务端为当前行棋方开启 30s 倒计时定时器
  - [ ] 每次收到走步消息后，重置倒计时并切换行棋方
  - [ ] 若一方倒计时结束仍未操作，服务端判定其“超时负”或自动为其选择随机合法走步，并广播游戏结束

- [ ] **4.3 悔棋与认输同步**
  - [ ] 客户端发送悔棋请求 -> 服务端转发给对手 -> 对手点击弹窗同意/拒绝 -> 服务端接收结果并选择是否回滚 `BoardState` 并同步
  - [ ] 任何一方点击认输 -> 客户端向后端发送 `surrender` -> 服务端广播游戏结束
